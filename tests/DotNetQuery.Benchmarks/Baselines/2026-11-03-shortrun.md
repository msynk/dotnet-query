# Benchmark baseline - 2026-11-03 (ShortRun, indicative)

Second committed baseline, after the hot-path allocation work and with the new suites (large updates, infinite-query
memory, persistence throughput, eviction, the comparison with `MemoryCache`, and Blazor rendering). ShortRun uses 3
iterations, so the Error column is wide: compare **Allocated** precisely and **Mean** only for large differences.
Reproduce with:

```bash
dotnet run -c Release --project tests/DotNetQuery.Benchmarks -- --job short --filter "*FetchBenchmarks*" "*CacheComparison*"
```

## Changes since the 2026-11-02 baseline

| Benchmark | 2026-11-02 | 2026-11-03 | Why |
| --- | --- | --- | --- |
| `FetchBenchmarks.CachedHit` allocated | 432 B | 104 B | entry lookup without a closure, no per-call closure for the fetch request, completed tasks reused while the state is unchanged |
| `FetchBenchmarks.CachedHit` mean | 137 ns | 122 ns | (within ShortRun noise) |
| `FetchBenchmarks.ForcedRefetch` allocated | 1,336 B | 1,224 B | the same entry lookup; attempts call the fetcher directly when no limiter, rate limiter or timeout is configured |
| `FetchBenchmarks.ColdFetch` allocated | 2,040 B | 2,183 B | +143 B for the scheduling, adaptive-polling and batching features added since (creating an entry is the slow path) |
| `NotificationBenchmarks` (1 observer) allocated | 248 B | 152 B | the entry lookup behind `SetQueryData` |

The `AllocationBudgetTests` measure the same path without the benchmark's own `await`: 488 B/op before, 32 B/op after.

## Reading the comparison

`CacheComparisonBenchmarks` serves one cached value three ways. A `ConcurrentDictionary` of tasks is the floor (no
expiry, no notifications, no deduplication of concurrent misses); `MemoryCache.GetOrCreateAsync` adds expiry; a
DotNetQuery hit additionally resolves the query's options (prefix defaults), checks staleness under the entry lock,
records the fetcher for invalidation and signal refetches, and returns a `QueryResult<T>` - roughly 120 ns and
about 100 bytes, which is the price of those features on the read path.

`BlazorRenderBenchmarks.RenderFromWarmCache` is dominated by bUnit's test renderer (it parses the produced markup
with AngleSharp); `ReRenderOnCacheWrite` - a cache write re-rendering a mounted `<Query>` - is the representative
number.
